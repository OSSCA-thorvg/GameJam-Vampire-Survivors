# 0019. Render actor and effect motion with native Lottie

- Status: Accepted
- Date: 2026-11-08
- Related issues: #84; partially supersedes ADRs 0003, 0007 and 0016 for animated instances and the current motion inventory

## Context

REQUIREMENTS 10–12 retain ThorVG, replaceable assets and worker ownership. On 2026-11-08 the user requested all visual motion in Lottie and explicitly included newly produced idle/locomotion for players, enemies and bosses plus projectiles/effects. The approved pixel corpus from #76 contains 84 logical IDs, including four character designs; gameplay selection and per-character stats are supplied by #14 and remain unchanged by this migration.

Pinned ThorVG 1.1.3 proves native segments, independent controllers and same-origin image resources work; Picture duplication is a frozen snapshot. The genuine Swift/Bat worker WebGL pilot passed the bounded image-bank/HOLD remap/native parent-opacity profile, flipping and all93 feedback samples. On Apple M4 Pro, Chrome156/ANGLE Metal at1280×720, native capacities were180.25 MiB normal mixed caps,311.5625 MiB synthetic six-type prewarm and730.5625 MiB for3000 bats with all12 poses warmed. The50-second stress observation had median59.95fps, first cold window21.57fps and later minimum55.96fps. Final-pack measurement separates two seconds of real rendered settling from a50-second warm observation, retaining cold timings separately. Other actors in this pilot reused diagnostic stills; this proves runtime capacity and the two pilot gaits, not the complete corpus.

Repeated source pilots exposed a separate premise failure: four-idle/eight-walk horizontal rows generated on the same 2172×724 canvas change figure scale. Upstream has no Codex image-size dial; an offline prepare test confirms explicit eight-frame idle at 4 fps is supported and yields identical 1536×192 state guides. Swift004 shows equal columns alone are insufficient: the provider also changes drawing magnification between the padded base identity and the tightly cropped action anchor. A separate experiment exactly reproduces all 16 canonical PNGs with the official whole-row fit, then uses one final bank factor/palette. Final 96-pixel native idle/move motion-presence values exceed the unchanged 0.01 threshold, and the head/torso/baseline comparison is consistent. This adopts declared upstream camera normalization; raw-global candidates remain rejected and full temporal review remains mandatory.

## Alternatives considered

- **Retain static actors or animate one still** — does not satisfy the explicit idle/locomotion request.
- **Sprite-atlas or JavaScript pose playback** — introduces another playback format instead of the requested native Lottie.
- **Duplicate animation Pictures** — copies a rendered snapshot, not an independent controller.
- **Tick hidden prewarmed instances** — prepares decoded poses and spends memory without visible benefit.
- **External opacity mask** — pinned native negative-X rendering fails; retain this as rejected research.
- **Unmeasured bulk conversion** — risks producing a corpus the native runtime cannot sustain.

## Consequences

Animation increases native decoded-image memory and controller cost. The pilot is a release gate, and a failure must be resolved explicitly before bulk work. Runtime tests must cover active lifecycle, native marker-relative boundaries, exact feedback phases, bounded resource parsing and independent playback. Every source row needs temporal review; a changed art direction requires explicit user evidence and new exact-bank reviews. Production excludes gallery motion controls and test diagnostics. A ThorVG upgrade must re-prove native playback, slots, caching, ownership and performance.
